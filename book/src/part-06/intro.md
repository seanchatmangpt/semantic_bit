# Part VI — SHACL Admission

To enforce the shapes required by our domain vocabulary, we admit SHACL (Shapes Constraint Language) into our architecture. SHACL allows us to define the structural conditions a graph must meet to be considered valid.

Just as a condition code gatekeeps entry into a semantic channel, a SHACL shape gatekeeps entry into our admitted graph structure. It defines constraints such as:
- **Property Constraints**: A `Record` must have exactly one `length` property of type `xsd:integer`.
- **Node Constraints**: A `Channel` must only connect nodes of type `Subsystem`.
- **Value Ranges**: A `BitOffset` must be greater than or equal to 0.

When we receive an RDF graph—whether generated by a human, an automated system, or derived from source code—we validate it against our SHACL shapes. If it fails, it is rejected, just as a malformed control record is rejected. This provides a mathematically provable boundary for our specifications, guaranteeing that downstream tools (like code generators or documentation builders) will always receive data in the exact structure they expect.
